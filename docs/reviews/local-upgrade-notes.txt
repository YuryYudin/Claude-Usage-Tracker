THIS DMG IS A LOCAL BUILD

The app and embedded code are ad-hoc signed, not Developer ID signed or notarized.
The signature seals the bundle; it does not grant the old app's Keychain identity.
The inherited Keychain policy disables file-based login-Keychain access for
ad-hoc builds. Credentials still stored inline in legacy profiles are retained
when Keychain writes are unavailable. Credentials stored only in Keychain may
be unavailable to this build. Do not assume signing prompts alone fix that.

The working installation was confirmed to be ad-hoc signed with no Team ID.
The reviewed old fork already falls back to inline profile credentials when its
exclusive data-protection Keychain access is unavailable in an ad-hoc build.
The new build preserves this behavior. A Developer ID certificate is not required
for upgrading that setup. The Keychain-only caveat applies to accounts whose
credentials were actually moved to Keychain by a different or entitled build;
signing metadata alone does not inventory the saved credentials.

If macOS blocks opening this local build, Apple's per-app procedure is under
System Settings > Privacy & Security > Open Anyway. Do not disable Gatekeeper.
https://support.apple.com/en-gb/102445

WHAT THE MIGRATION PRESERVES

The preferences domain remains HamedElfayome.Claude-Usage. Migration accepts the
fork's profiles_v3 records and keeps IDs, order, active profile, Codex executable,
home and SSH targets, GLM settings/keys, selected quotas, display configuration,
refresh intervals, notifications, and usage history. Provider-specific tray
metrics become the shared usage metric while preserving their display settings.
Existing Codex CLI accounts are not switched to HTTP.

Before its first compatibility save the app stages a private defaults/history
backup under ~/Library/Application Support/Claude Usage/migration/:
  before-provider-integration.plist
  history/*.json
The backup contains preferences and history, not a Keychain export. It is not
overwritten on later launches. Corrupt records, failed backups, and detected
external changes block saving. Missing credential hydration cannot delete items.

BEFORE REPLACING YOUR WORKING INSTALLATION

1. Quit the working app and preserve its app bundle as a ZIP backup.
   Avoid running the old and new builds together; they share preferences.
2. Privately back up its preferences and the entire "Claude Usage" Application
   Support folder while it is stopped. Do not delete Keychain items or CLI files.
3. The reviewed ad-hoc fork uses inline fallback and CLI-owned credentials;
   this candidate preserves those sources. A certificate-signed build needs to
   be checked separately if credentials are known to exist only in Keychain.
4. Replace the app only after preserving the old build and data. Open the
   installed copy at /Applications/Claude Usage.app, check all existing accounts,
   usage, history, settings and refresh. Eject the DMG after copying.
   Check widgets from the installed extension and select Extra Large.
   Existing profile IDs and settings are retained. Kimi is a new provider;
   older builds cannot fetch its quota. App and widget snapshot schema advance
   together to version 5, so replace the full app bundle.

BACKUP COMMANDS

Quit Claude Usage first. Run these in Terminal before copying the new app into
Applications. They create a private backup, without printing credential values:

umask 077
backup_dir="$HOME/Library/Application Support/Claude Usage Recovery/$(date +%Y%m%d-%H%M%S)-build23.noindex"
mkdir -p -m 700 "$backup_dir"
ditto -c -k --sequesterRsrc --keepParent "/Applications/Claude Usage.app" "$backup_dir/Claude Usage.app.zip"
defaults export HamedElfayome.Claude-Usage "$backup_dir/preferences.plist"
if [ -d "$HOME/Library/Application Support/Claude Usage" ]; then
    ditto "$HOME/Library/Application Support/Claude Usage" "$backup_dir/Application Support"
fi

Confirm the ZIP backup and preferences.plist exist in the backup folder before
replacing the installation. Keep this backup private; it can contain credentials.
Keep old app backups compressed so they cannot become duplicate launch targets.

ROLLBACK

For rollback from build 23 to build 20, restore the archived app while keeping
current preferences and credentials. The six existing providers use the same
profile format. The older app retains a Kimi record as an unsupported provider;
it cannot display or refresh it. Never run a pre-integration legacy app on the
current preferences.

For rollback to a pre-integration legacy build, the old fork cannot decode the
new "anthropic" provider value. Replacing only
the app bundle is insufficient; its original metadata format must be restored.
Do not blindly restore old OAuth token values: refresh may have rotated them.
Preserve/reconcile the newest credentials by profile ID when restoring metadata.
Never replace current auth.json, SSH keys, Claude credential files, or Keychain
items with frozen token snapshots. Changes to accounts need reconciliation too.
